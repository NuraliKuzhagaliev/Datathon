This is a factual supplement to B's three-minute product walkthrough. A synthetic rehearsal must be labeled. Do not present the current detector as competition-ready.

0:00–1:00 — Problem and operator flow. MOV upload creates a durable case; processing ends in exactly violation/no_violation or a separate technical failed state. An operator can inspect source evidence, record a separate decision and export the case. Reviews never change the automatic jury response.

1:00–2:00 — Local architecture. One React UI is shared by the web service and Electron shell. FastAPI handles authenticated upload/poll and UI routes; SQLite WAL preserves cases; a supervised spawned GPU worker runs pinned Qwen3-VL-2B-Instruct locally on RTX 4060. The prepared package includes Python/CUDA libraries, model assets, FFmpeg and rules. There is no cloud AI inference, identity analysis or audio analysis. Source PTS, rather than frame/30, drives timestamps; rotated VFR video and preview mapping have regression coverage.

2:00–3:00 — Evidence and legal scope. Candidate screening is followed by contextual verification. Positive events require complete applicable predicates and no exclusion, stable event IDs and 1–3 unannotated source JPEGs. Exact public rule-source bytes are saved per case and hashed in the export. Only Resolution No. 231 paragraph 22 is enabled experimentally; six other researched candidates are disabled. A negative result covers only the enabled scope and is not a compliance certificate.
