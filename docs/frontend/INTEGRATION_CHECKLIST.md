# Интеграция A + B: от адреса сервера до готового показа

**Обновление B 18 октября 2026.** Реальные API и полный EXE-прогоны на A выполнены, комплект модели собран. Независимый запрос B: сайт 200, публичный health и подготовленный туннель health — 502. Владелец поручил B объединить PR #4 и обновить сайт; успешная публикация статики не подтверждает восстановление API. [Текущий общий аудит](../integration/PROJECT_STATUS.md) отделяет исторические результаты от текущей готовности.

Авторитетная схема: `packages/contracts/openapi.json`, версия **1.0.0**. Для desktop: `packages/contracts/desktop-launch.schema.json`. A отвечает за backend, модель, нормы и объединение веток; B — за интерфейс, клиент и Windows-оболочку.

## 1. Что A передаёт B

| Нужно | Формат |
| --- | --- |
| Доступный URL | `https://<адрес-команды>`: схема, хост, порт при необходимости. Ссылка на GitHub не подходит. |
| Операторский ключ | Через приватный канал или непосредственный ввод в интерфейс. Не в Git, URL, скриншотах или этом документе. |
| Версия | Контракт 1.0.0, commit backend, версии модели и реестра норм. |
| Запуск | Реально выполненная A команда и расположение зависимостей. B не угадывает способ запуска Python. |
| Готовность | Ответ `/health/ready`, выполнен ли первый прогон на RTX 4060. |
| Проверочные случаи | Локально проверенные положительный и отрицательный примеры, случай с несколькими событиями, отдельный непригодный тестовый файл. Передача материалов только локально. |
| Автономный комплект | Полная папка `releases/backend` с `launch.json`, моделью, средой выполнения и FFmpeg. Для первого веб-подключения не требуется. |

**На разных ПК `127.0.0.1` указывает на разные компьютеры.** Адрес A `http://127.0.0.1:8000` не откроет его сервис с ПК B. Нужен доступный B адрес. Подключённый Windows-клиент допускает HTTPS или HTTP только на loopback.

## 2. Подготовить общую ревизию и подключение

1. Финальные правки B: **PR #4**, `codex/frontend-polish` → `codex/integration`, на базе `ea69728532a07d7bf9da85ee321f542c389c63b5`. Владелец разрешил B объединить PR и обновить сайт. После merged-статуса использовать общую вершину `codex/integration`; старую `codex/frontend` повторно не объединять.
2. Сверить общий commit и контракт 1.0.0. `main` требует отдельного разрешения и в эту операцию не входит. Полный Windows-пакет A пересобирает с итоговой общей ревизии.
3. Из корня объединённого репозитория выполнить существующие команды B:

```powershell
pnpm install --frozen-lockfile
pnpm check:ui
pnpm build:web
```

4. A обслуживает `apps/web/dist`, `/api/*` и `/health/*` с одного адреса. Открыть интерфейс **без `?demo=1`**. Для разработки через Vite:

```powershell
$env:CASHPROOF_DEV_BACKEND = 'https://<адрес-команды>'
pnpm dev:web
```

Заменить placeholder реальным адресом. Уже работающий Vite сначала остановить в его терминале: он не подхватит новую переменную сам. Открыть `http://127.0.0.1:5173/`, ввести ключ в интерфейсе. Ключ не нужен в исходниках или `VITE_*`.

## 3. Первый совместный проход: ориентир 45–60 минут

Это организационный план после готовности A, не обещание срока исправления модели или сервера.

| Этап | Кто | Ориентир |
| --- | --- | --- |
| Адрес, контракт, вход | A + B | 0–10 мин |
| Настоящая загрузка и завершение задачи | A + B | 10–20 мин |
| Кадры, время, применимость нормы | Человек локально + A + B | 20–35 мин |
| Решение, повторный вход, ZIP | A + B | 35–45 мин |
| API жюри и ошибки | A + B | 45–60 мин |

Автономность, нагрузка и внешняя доступность проверяются отдельно после первого прохода. При блокирующей ошибке фиксируется шаг и владелец, затем выполняется повторная проверка.

## 4. Матрица приёмки

Изначальные статусы обновлены по фактическим протоколам A. Частичное подтверждение не является PASS всего составного критерия. PASS ставится после наблюдения на настоящем сервисе. Реальные кадры, тексты и ответы API остаются локально. В общий отчёт достаточно номера проверки, HTTP-кода, длительности и пути ошибочного поля схемы.

| ID | Действие и критерий PASS | Кто | Статус |
| --- | --- | --- | --- |
| I01 | Открыть интерфейс и «Систему». Нет синтетической маркировки. `/health/ready`: 200, `ready=true`, `mode=server`, `contract_version=1.0.0`. При прогреве допустим 503/false, но обработка ещё не готова. | A + B | ЧАСТИЧНО: ready/server/1.0.0 получен ранее; 18 октября B получил публичный health 502 |
| I02 | Отсутствующий/неверный ключ дают 401 на защищённых API; правильный операторский ключ открывает список. Health не доказывает авторизацию. Ключ не попадает в URL и localStorage. | A + B | PASS на A: реальные ключи/scopes; UI storage/URL — синтетические проверки |
| I03 | Загрузить настоящий MOV. Multipart поле `file`; POST возвращает **202** и `job_id`; UI открывает именно это дело. Передача файла и обработка различимы. | B | PASS на A: новый реальный MOV через UI/API; не независимый ПК B |

UI/jury совпадают по индексам, типам, времени и кадрам. | A | ЧАСТИЧНО: проекции совпадают; положительные события — синтетические проверки |

Нет синтетики или изменённых пикселей доказательств. События упорядочены по времени. | Человек + A | НЕ ПРОВЕРЕНО: человеческая приёмка реальных положительных/нескольких событий |
| I07 | Включить видео, перейти к событию, проиграть контекст, сменить вид. MIME `video/mp4`, авторизация, сохранение пропорций, монотонная `time_map`. Человек сверяет начало, конец и события с оригиналом. Смена вида сохраняет позицию и заметку. Не считать время по фиксированным 30 кадрам/с. | Человек + B | ЧАСТИЧНО: VFR/rotation/MP4 и mapping проверены; семантическая сверка человеком открыта |

Новая версия библиотеки не переписывает старое дело. | Человек + A | ЧАСТИЧНО: официальный snapshot/реестр; применимость к реальному событию не принята |

## 5. Точки стыка

| Запрос | Ожидаемый ответ | Назначение |
| --- | --- | --- |
| `POST /api/v1/analyze` | 202, `UploadAccepted` | MOV в поле `file` |
| `GET /api/v1/jobs/{job_id}` | 200, processing/done/failed по схеме | Отдельный клиент жюри |
| `GET /api/ui/cases` | 200, `CaseList` | Вход и список |
| `GET /api/ui/cases/{job_id}` | 200, `CaseDetail` | Этапы, результат, события, снимок норм |
| `PUT /api/ui/cases/{job_id}/reviews/{event_id}` | 200, `Review` | `decision`, `note` до 2000 символов |
| `GET /api/ui/rules` | 200, `RuleRegistry` | Библиотека |
| `GET /api/ui/cases/{job_id}/media` | 200 `video/mp4`; 409 пока не готово | Видео для просмотра |
| `GET /api/ui/cases/{job_id}/bundle` | 200 `application/zip`; 409 пока не готово | Серверный архив |
| `DELETE /api/ui/cases/{job_id}` | 200 по OpenAPI | Намеренная очистка тестового дела |
| `GET /health/live` | 200 | Жив процесс, не доказательство готовности модели |
| `GET /health/ready` | 200 или 503, `HealthReady` | Готовность и версия контракта |

Все API требуют `X-API-Key`; health публичные. Обязательные поля `CaseDetail` передаются даже пустыми — `null`/массивы согласно схеме. Нельзя менять тип, время или идентификатор события только в одной из UI/jury-проекций.

## 6. Если что-то не работает

| Симптом | Первый шаг | Кто исправляет |
| --- | --- | --- |
| У A открывается, у B нет | Проверить адрес с B, HTTPS, порт и доступность. `localhost` на ПК разный. | A |
| 401 | Приватно проверить ключ и права endpoint. Не добавлять ключ в URL. | A + B |
| Ошибка контракта | A локально валидирует JSON; B получает путь ошибочного поля и ожидаемый тип. Не отключать валидатор вслепую. | A; при ошибке клиента B |
| Видео не играет | MIME, кодек, `media_ready`, 409, карта времени и длительность скачивания. | A + B |
| Не совпадают кадр/время | Остановить показ этого результата; локально проверить индекс, timestamps, edit lists/rotation и `time_map`. | A |
| Решение пропало | Проверить PUT, сохранение, последующий GET; исключить режим синтетики. | A + B |
| Неверное содержимое ZIP | Локально сверить дело, файлы и хеши. | A |
| Desktop не находит модель | Подключиться к серверу команды либо получить полный автономный комплект. | A |

## 7. Что ждёт автономная оболочка

- `launch.json`: `contract_version`, `executable`, `args_prefix`, `cwd`, `env`. Версия 1.0.0, пути внутри комплекта, без вшитых ключей.
- `args_prefix` содержит только флаги интерпретатора, например `["-s"]`. Electron добавляет `-m cashproof.bootstrap --host 127.0.0.1 --port 0 --data-dir <данные>/cases --frontend-dir <ресурсы>/web` и случайный ключ текущего запуска.
- В stdout нужна строка JSON с полями `event: http_ready` и `port: фактический порт`, завершённая переводом строки. Ожидание до 60 секунд.
- Затем health: `ready=true`, `mode=offline`, `contract_version=1.0.0`, ожидание до 240 секунд. Лимиты запуска не заменяют лимит обработки видео.
- Модель и зависимости подготовлены заранее. После получения комплекта A: `pnpm build:desktop`, затем I17–I18. Connected-сборка модель не включает.

## 8. Протокол результата

```text
Проверка: I__
Дата / проверяющий:
Общая ревизия / контракт:
Режим: веб / подключённый Windows / автономный Windows
Результат: НЕ ПРОВЕРЕНО / PASS / FAIL
HTTP-код / путь поля схемы / длительность:
Как воспроизвести (без содержания дела):
Кто исправляет:
Повторная проверка:
```

Ключи, кадры, тексты реальных наблюдений, архивы и необработанные ответы API остаются в закрытых локальных материалах.

**Для настоящего показа:** I01–I11 на проверенных делах. Для сдачи/API — также I12–I15. Для подтверждения Windows-клиента — I16. Для заявления об автономности — I17–I18. Невыполненные пункты обозначаются явно.

Отдельно A передаёт оценку качества: размер выборки, разбиение без одинаковых видео по обе стороны, precision/recall, ошибку времени, p50/p95 задержки и ограничения. Этот чек-лист их не подменяет.
