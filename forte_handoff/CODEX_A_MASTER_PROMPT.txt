INFERENCE DESIGN

Implement an inspectable, bounded pipeline:

Ingest -> validate/decode -> timestamp-preserving sample plan -> complete-video coarse screening -> candidate windows -> finer local verification -> verified rule predicates -> merge events -> raw JPEG evidence -> immutable jury result and richer review record.

Decode with FFmpeg/ffprobe or a reliable local decoder. Use actual presentation timestamps after applying container timing/rotation, with zero at the first displayed frame. Keep a mapping to the original frame and to the browser MP4 preview. A generated time from frame_index/30 is unacceptable. Validate every chosen evidence timestamp and frame against its source. Preserve aspect ratio. Do not resize the 464×848 source into a distorted square or pretend upscaling restores details.

Start with bounded windows that cover the complete video, including low-motion intervals. A starting experiment is 28-second windows with 4-second overlap, uniform roughly 1 fps sampling and a bounded number of motion-selected additional frames. This is an experiment, not a fixed performance promise. Give each sampled frame a stable ID and its actual time. Ask the local model for observable predicates, candidate event category, relevant frame IDs and uncertainty in a strict JSON structure. It must choose verified rule IDs, not write legal citations from memory. Validate output and allow at most one bounded repair. Reject invented frame IDs, out-of-range times and unsupported facts.

For candidate events, inspect a shorter original-video interval at a higher sampling density and sufficient spatial detail. Verify the alleged action AND a plausible benign explanation using the same observed context. Context windows must be large enough for transaction boundaries and omitted steps. For omissions, identify the expected step, the visible start/end of the relevant sequence, and why a missing step can be observed; an occluded interval is not negative evidence. Pick the first instant at which the omission is supportable. Record unobservable intervals in coverage metadata. Do not make a legal verdict directly from an unsupervised anomaly score.

Cap the candidate budget based on measurements, but log coverage and do not quietly truncate a multi-event video. If a cap prevents a valid complete result, expose the technical limitation instead of fabricating certainty. Avoid loading two large models simultaneously. Reuse the model and image encodings where practical. Only add a lightweight detector such as appropriately licensed YOLOX if the local evaluation shows a useful improvement. A standard COCO detector cannot be assumed to recognize banknotes, seals or a specific cashier workflow.

Known-rule verification and whole-video screening should complement one another. A previously unseen event may still satisfy a known, verified legal predicate. A generic unusual action without a supportable rule is a separate review cue, not an invented legal category. Do not claim detection of arbitrary unknown violations.
